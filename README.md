A compact, production-ish pipeline that converts unstructured text into a **Knowledge Graph** using a **multi-step LLM workflow**:

1) **Entities** → 2) **Relations** → 3) **Personality Traits (OCEAN)** → 4) **Sanity/Dedup** → Graph build & export.

Runs **offline by default** (deterministic mock LLM). Swap one class to use your real LLM provider.

## Use a Real LLM

Implement a tiny adapter (example: OpenAI) and swap it in:

```python
from openai import OpenAI
class OpenAILLM:
    def __init__(self, model="gpt-4o-mini", api_key=None):
        self.client = OpenAI(api_key=api_key); self.model = model
    def chat(self, messages, response_format=None):
        resp = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            temperature=0.1,
            response_format={"type":"json_object"}
        )
        return resp.choices[0].message.content
```

```python
# In the notebook:

# pipeline = MultiStepPipeline(llm=llm, doc_id="DOCX")
# ents, rels, traits, G = pipeline.run(your_text)
```

**Tips**
- Keep temperature **low** for extraction.
- Prefer JSON mode / function-calling if supported.
- Cache intermediate JSON while iterating.

## How the Pipeline Works

**Goal:** Convert raw text → consistent graph with evidence & confidence.

**Stages**
1. **Entities:** Extract `Person`, `Org`, `Project`, `Location`, `Date`, `Product` (+ aliases & evidence)  
2. **Relations:** Typed edges (e.g., `WORKS_FOR`, `LOCATED_IN`) with evidence & confidence  
3. **Traits (OCEAN):** For `Person` → trait edges with `score`, `confidence`, `observed_at`, `method`, **evidence**  
4. **Sanity/Dedup:** Alias merge per type; canonicalize references  
5. **Graph Build:** **NetworkX MultiDiGraph**; relation edges and trait edges (to `TRAIT::…` nodes)

## Data Model (Core Schemas)

```python
class Evidence: doc_id:str; sent_id:int; char_start:int; char_end:int; text:str
class Entity: id:Optional[str]; name:str; type:str; aliases:List[str]; mentions:List[Evidence]
class Relation: head:str; relation:str; tail:str; evidence:Evidence; confidence:float
class TraitObservation:
    subject:str; trait_id:str; trait_label:str
    score:float; confidence:float; observed_at:Optional[str]; method:Optional[str]
    evidence:Evidence
```

**Trait Pattern:** `(:Person)-[:HAS_TRAIT {score,confidence,observed_at,method,evidence}]->(:Trait)`

## Query Examples (Python)

```python
def people_at(G, org_name):
    return [(u, d['relation'], v, d.get('evidence',{}).get('text'))
            for u,v,k,d in G.edges(keys=True, data=True)
            if d.get('kind')=='RELATION' and d.get('relation')=='WORKS_FOR' and v==org_name]

def collaborations(G, name):
    return [(u, v, d.get('evidence',{}).get('text'))
            for u,v,k,d in G.edges(keys=True, data=True)
            if d.get('kind')=='RELATION' and d.get('relation')=='COLLABORATES_WITH' and (u==name or v==name)]

def top_trait(G, trait_id, k=5):
    scores = {}
    for u,v,kd,d in G.edges(keys=True, data=True):
        if d.get('kind')=='TRAIT' and v==f"TRAIT::{trait_id}":
            scores[u] = max(scores.get(u,0.0), d.get('score',0.0))
    return sorted(scores.items(), key=lambda x:x[1], reverse=True)[:k]
```

## Neo4j Export & Import

The notebook writes:
- `kg_nodes.csv` → `id,label,name,aliases`  
- `kg_edges.csv` → `start_id,end_id,type,kind,confidence,score,observed_at,relation,method,evidence_json`  
- `neo4j_import.cypher` → generated script

**Steps**
1. Copy CSVs + Cypher to Neo4j’s **import** directory.  
2. In Neo4j Browser, run the generated script (uses APOC `apoc.merge.*`).  
   - Creates constraints, loads nodes, then relationships with evidence JSON.

> Without APOC, replace with standard `MERGE` statements.

## Evaluation & Tips

- **Extraction sanity:** spot-check entities/relations on 1–2 docs  
- **Graph health:** duplicate rate, orphan nodes, type/label violations  
- **Traits:** each trait edge must have **evidence** & **confidence**  
- **Ablation idea:** try stricter vs. looser relation prompts; compare % valid edges

**Common pitfalls**
- Non-JSON output → keep JSON mode on (wrapper already re-parses).  
- Duplicates → tweak alias threshold; add embedding similarity or LLM-assisted merge.  
- Sparse traits → ensure inputs have personality cues; allow lower-confidence with evidence.
